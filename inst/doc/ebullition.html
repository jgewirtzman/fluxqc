Most chamber users (upland soils, upland tree stems) never meet ebullition and never need this vignette: the core path of stemflux (goFlux -> best.flux -> flag_detection -> qc_screens, wrapped by process_fluxes()) does not call any of the code below. Over water, saturated peat or flooded stems, bubbles add abrupt step-ups to the smooth diffusive rise, and one linear or Hutchinson-Mosier fit through both components gives a number that is neither. This add-on is switched on with a single argument, process_fluxes(ebullition = "flag" | "split"), or used directly through detect_ebullition(), split_ebullition() and merge_ebullition().

A real closure with bubbles

Example e of stemflux_examples() is a real 276 s floating-chamber closure on open water at site CP40 (Christian Point, a ghost-forest mangrove site) of the NASA BlueFlux campaign (ABB/LGR GLA131, “LGR2”). Geometry: Area 324.3 cm2, Vtot 4.318 L, Tcham 28.7 C (site-day mean air temperature), Pcham 101.325 kPa. We put it next to the clean tree-stem closure a for comparison.

What the trace shows, checked against the campaign’s own segmentation (output/ebullition/placements_summary.csv, all_traces.rds): CH4 rises diffusively from the first sample (about 11 ppb s-1) while CO2 rises cleanly from t = 0, so the chamber was already sealed when this window starts (the placement overlaps the campaign’s processed flux 44857_CP40_Water_78). At 42-46 s the CH4 jumps by about 675 ppb in five consecutive 1 Hz samples (112-160 ppb each), then resumes a steady rise to 4600 ppb. The campaign script, which tests single samples against a 100 ppb step, recorded those five samples as “5 jumps”. They are one bubble burst, not five bubbles and not the closure onset; stemflux merges consecutive flagged samples into one event by default (merge.consecutive = TRUE). No closure in the campaign’s archive shows several isolated steps on a clean baseline (all its flagged traces are bursts of consecutive samples), which is why this one is shipped.

Step 1: detect events

detect_ebullition() works on the flagged rows of each UniqueID. The default method follows Hoffmann et al. (2017): the point-to-point changes are compared with quartile fences Q3 + k * IQR; stemflux’s default k = 3 keeps Gaussian noise below the fence on 600-point closures (k = 0.25 reproduces Hoffmann’s own fences, which were used to select fitting windows rather than to sum bubbles). Detected events are overlaid on the trace. On this closure the IQR fences (threshold about 17 ppb per sample, set by the closure’s own noise) also catch the shoulders of the burst, so the merged event carries about 1100 ppb; the campaign’s fixed 100 ppb criterion gives 676 ppb in five samples (shown last).

Two alternatives are available: method = "threshold" (a fixed jump size in gas units, the criterion used in the BlueFlux processing) and method = "runvar" (running variance of the changes above a cutoff, after the description of So et al. 2024).

detect_ebullition(both, "CH4dry_ppb", method = "threshold", jump.thresh = 40)$summary$n_events
#> [1] 0 1
detect_ebullition(both, "CH4dry_ppb", method = "runvar", runvar_window = 5, runvar_cutoff = 30)$summary$n_events
#> [1] 11  1

sp$diffusive has goFlux’s shape: the gas column now holds the de-ebulliated trace, the raw values are kept in CH4dry_ppb_raw, and the equilibration buffer around each event has flag = 0, so goFlux ignores it. (The clean closure a is untouched: no events, all rows keep flag = 1.)

For the BlueFlux closure the ebullitive term is the summed bubble mass divided by the closure duration, converted with that chamber’s flux.term; ebullitive_fraction says how much of the total came from bubbles. (The campaign’s own processing counted 5 single-sample jumps totalling 676 ppb in this closure; method = "threshold", jump.thresh = 100, merge.consecutive = FALSE reproduces that count exactly.)

The same through process_fluxes()

The add-on is an option of the pipeline, not a separate path. "flag" fits the whole trace but records the events; "split" fits the diffusive term on the de-ebulliated trace. Per-closure control comes from ebullition_ids or a logical ebullition column in the auxfile, so flooded stems can be split while upland stems in the same call run the core path.

aux <- data.frame(UniqueID = c("2021-05-18_5086_I_7.0", "BF_CP40_2022-10-23_P06"), ebullition = c(FALSE, TRUE))
invisible(capture.output(       # goFlux's progress bar is captured
  res <- suppressWarnings(process_fluxes(both, aux = aux, gastype = "CH4dry_ppb",
                       qc = list(c0 = TRUE, convex = TRUE),
                       ebullition = "split", ebullition_method = "iqr"))))

How other packages handle ebullition

Checked in September 2026 from the sources or manuals named; “not verified” marks claims that could not be checked.

goFlux 0.2.0 none: one LM and one HM fit per closure, no mention of ebullition in the source tree source snapshot
Hoffmann et al. 2017 (AMT 10:109-118), R script on Zenodo record 53168 quartile fences Q1 - 0.25 IQR, Q3 + 0.25 IQR on the point-to-point changes; a moving-window linear fit is accepted only when all its changes lie inside the fences; diffusion from accepted windows, ebullition from the rest script lines 365-366, 457-458
fluxCH4 (github.com/mthayne527/fluxCH4; standalone scripts) GAM per id (diffusive if R2 > 0.99), otherwise GBMs via dismo::gbm.step; smoothed residuals, dynamic threshold (SD x multiplier) and a concentration-difference quantile test flag points; flagged points grouped into sequences (5-point buffer, minimum length) = events; floating chambers README

gasfluxes 0.7-2 linear, robust linear (MASS), HMR, NDFE; no ebullition or piecewise handling mentioned CRAN manual

None of these packages is a dependency of stemflux; the survey is documentation only.

Provenance and citation etiquette

No code was copied from Hoffmann et al. (2017)’s Zenodo script (record 53168, R-Script-CH4_version_1.0.R) or from the fluxCH4 repository. The "iqr" method was re-implemented from the paper’s description and then checked against the script’s fence definitions (lines 365-366 and 457-458 of that script define Q1 - Jumper*IQR and Q3 + Jumper*IQR on diff(y) with Jumper = 0.25); the per-closure application, the event-mass accounting and the equilibration buffer are stemflux’s own. The "runvar" method was written from the published description of So et al. (2024) without access to their code. The "threshold" method is stemflux’s own. For the record: the Zenodo record’s license field reads “other-open” (open access, no standard license named), and the fluxCH4 repository carries an MIT LICENSE file whose copyright line is the unedited template (“First Last”); since nothing was copied from either, neither license is exercised.

If you publish results obtained with the add-on, please cite the method alongside goFlux and stemflux:

  • method = "iqr": Hoffmann, M., et al. (2017). Atmos. Meas. Tech. 10, 109-118. doi:10.5194/amt-10-109-2017
  • method = "runvar": So, J. S., et al. (2024). J. Geophys. Res. Biogeosciences. doi:10.1029/2024JG008035
  • goFlux: Rheault, K., Christiansen, J. R., & Larsen, K. S. (2024). JOSS 9(96), 6393. doi:10.21105/joss.06393
  • stemflux: citation("stemflux")

Limitations

All three detectors are local tests. Slow bubble trains that raise the concentration over many samples are missed by "iqr" and "threshold"; analyzer artefacts (pressure transients, breaths on an inlet, valve switches) look exactly like bubbles; and the ebullitive rate assumes the bubbles caught in a 5-10 min closure represent the sampling period, which for episodic ebullition is rarely true. Review events against the traces before reporting, as was done by hand in the source campaign.
